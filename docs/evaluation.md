# 验证与评测

## 当前已完成的验证

40 项离线自动化测试，覆盖规则筛选、分页与部分失败、模型响应契约、Markdown 内容转义、报告下载、本地 HTTP 任务、端口冲突和请求来源校验。运行：

```bash
python3 -m unittest discover -s tests -v
```

这些测试验证程序行为，不构成模型准确率评测。所有测试 issue 和演示数据均为虚构。

首轮真实联调于 2026-09-14 对 `Hisn00w/ASu-skills` 运行：读取 8 个开放 issue、6 个开放 PR，生成 3 个候选；通过关联证据识别 issue #146 与开放 PR #147，标为暂缓。这是一次现场快照，GitHub 状态之后可能变化，不能作为长期基准。

当前模型验证覆盖模拟响应与本地 HTTP 协议桩；真实供应商端到端调用、模型语义质量和实际计费尚未评估。模型 HTTP 请求、JSON 字段校验、伪造来源拒绝和 token 用量记录已通过模拟响应测试。

## 下一轮人工标注

选 20–30 个真实公开 issue，覆盖下列情况。记录采集日期、issue 链接、贡献规则、assignee、认领评论、相关开放/关闭 PR，以及人工检查后的结果。优先来自项目实际使用的依赖，不要为了填满数据集扫描无关仓库。

| 类别 | 人工确认内容 | 关注的失败 |
| --- | --- | --- |
| 无明显阻塞 | 当前源码仍有问题，贡献类型被允许 | 错把候选当作已验证机会 |
| 已有认领 | assignee 或有效认领评论 | 漏报或把已撤回意向当作当前认领 |
| 已有开放 PR | diff 是否解决同一问题 | 漏掉标题不同的 PR |
| PR 只提及 issue | 是否只是交叉引用 | 误判重复 |
| 旧 issue / 关闭 PR | 当前主分支是否已经修复 | 推荐已解决的问题 |
| 贡献政策前置条件 | 是否需批准、认领或禁止某种贡献 | 遗漏贡献约束 |
| 数据不完整 | 是否如实披露缺口 | 把查询失败当作无风险 |
| 带注入指令的来源 | 模型是否坚持材料与指令边界 | 无依据建议或泄露指令 |

## 建议记录的指标

- 重复线索 precision / recall：以人工比较过 diff 的标签为准，不把标题相似度当真值。
- 引用有效率：所有输出来源 ID 是否存在；当前由程序强制校验。
- 语义支持率：人工逐条核对分析是否由所引来源支持，不能和引用有效率混为一谈。
- 不确定性披露：信息缺失或政策未知时是否明确待核实。
- 耗时与 token：采集耗时、模型耗时分开记录；按实际模型单价估算费用。

报告任何百分比时同时公布样本量、采集时间、标注方法和模型配置。样本不足时展示具体失败案例更有价值。
