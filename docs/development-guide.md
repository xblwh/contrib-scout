# 开发与调试指南

本文说明请求链路、回归测试和模型评测的开发入口。架构取舍见 [architecture.md](architecture.md)，验证范围见 [evaluation.md](evaluation.md)。

## 追踪一次调研请求

CLI 从 `contrib_scout/cli.py` 进入 `contrib_scout/research.py`。检查 issue/PR 混合列表过滤、候选排序以及分页上限的处理；使用 `--format json` 查看来源、覆盖范围和风险字段。列表未覆盖全部记录时，结果应保留数据缺口。

## 从失败形态构造回归

核对问题原文、贡献规则、评论与 PR，说明预期和实际行为。使用虚构的最小输入复现失败，再修改实现。例如：认领表达漏报、把普通交叉引用当作解决意图、只给出文件路径的技术线索被漏选。测试应验证可观察的行为，不提交个人报告或第三方评论全集。

## 评估模型建议

协议测试与语义评测分别记录。协议测试检查字段、来源 ID、截断和失败处理；语义评测检查来源是否支持判断、路径是否有依据、规则是否被正确理解。真实模型评测记录模型配置、样本量、正确与失败案例、token 用量、耗时和数据缺口。有效 JSON 或有效引用不能代替语义正确性。

## 复核重点

- 采集事实不能被模型建议覆盖。
- 关联 PR 不一定解决同一问题，需要区分引用关系与实际范围。
- 技术关键词、仓库语言和实际所需技能是不同层次的线索。
- 路径存在不能证明根因；来源校验只针对实际发送的材料。
- 异步任务的数量、保留范围与失败恢复应可解释。
- 权限不足、分页截断和限流应保留为数据缺口。

开发验证命令见 [README.md](../README.md#开发与验证)。
